## 这个项目解决什么问题

一个住宅小区的地下车库，有几百个车位、几百户住户，还有商户和访客。谁来停哪里？

朴素做法是「先到先得」或「按申请顺序排」，结果往往是：靠近单元门的车位被访客白天占满，新能源车主找不到充电桩，腿脚不便的住户被排到最远角落。这不是车位不够，而是**分配方式不对**。

本项目把车位分配建模成一个带约束的多目标优化问题，用遗传算法求解，在一秒内给出一个整体满意度明显更高的方案。

## 快速开始

无需安装任何依赖：

```bash

cd parking-ga-core

# 直接跑一个模拟车库
python -m parking_ga.cli

# 自定义规模，并把结果导出成 JSON
python -m parking_ga.cli --rows 5 --cols 10 --generations 50 --seed 2024 --json out.json
```

作为库使用：

```python
from parking_ga import GAConfig, GeneticAlgorithm, Problem, ParkingSlot, Permit, PermitCategory

problem = Problem(
    slots=[
        ParkingSlot("A01", x=0, y=0, has_charger=True),
        ParkingSlot("A02", x=2.5, y=0),
        ParkingSlot("A03", x=5.0, y=0),
    ],
    permits=[
        Permit(permit_id="P01", category=PermitCategory.RESIDENT,
               preferred_x=0, preferred_y=0, needs_charger=True),
        Permit(permit_id="P02", category=PermitCategory.VISITOR,
               preferred_x=12, preferred_y=0),
    ],
)

ga = GeneticAlgorithm(problem, GAConfig(generations=30, seed=42))
solution = ga.run()

print(solution.total_score)   # 0.7xxx
print(solution.as_dict())     # 可直接 json.dumps 的结构
print(ga.history)             # 每一代的最优分，可直接画图
```

## 设计思路

### 编码：排列 + PMX，而不是 0/1 矩阵

最直觉的编码是「N 个许可 × M 个车位」的 0/1 矩阵，但它的致命问题是**随机交叉和变异会产生非法解**（一个车位被两个许可占用，或一个许可占了两个车位），必须额外写修复算子，而且修复过程会破坏父代的优良结构。

本项目用的是**整数排列编码**：个体的第 i 位表示第 i 个许可占用车位池里的第几个车位。这样任意两个排列做**部分匹配交叉（PMX）**，子代天然还是排列，一车多占在编码层面就不可能发生。

> 编码层的合法性保证，比事后修复要优雅得多，也快得多。这是本项目最重要的一个设计决策。

### 适应度：三维评分

方案得分由三个正交维度加权构成，归一化到 [0,1] 后按权重汇总：

| 维度 | 权重 | 衡量什么 | 为什么需要它 |
| --- | --- | --- | --- |
| 步行距离 | 0.5 | 许可偏好点到实际车位的曼哈顿距离，指数衰减 | 停车体验最直接的感受 |
| 类型匹配 | 0.3 | 住户靠中心、访客靠边缘、员工居中；充电/无障碍需求是硬约束 | 避免访客挤占核心区，照顾特殊需求 |
| 空间利用 | 0.2 | 车位填充率，并对「访客占核心车位」施加惩罚 | 防止算法用少分配来换取平均分虚高 |

三者缺一不可：只看步行距离，算法会把所有人挤到入口；只看利用率，会退化成随机填满；只看类型匹配，则会忽略具体位置。

权重可通过 `FitnessWeights` 调整，`normalized()` 会自动折算成总和为 1，不需要手动凑数。

### 模拟退火：跳出精英陷阱

标准遗传算法有一个隐患：开局若碰巧遇到一个还不错但远非最优的个体，精英保留会把它供起来，种群多样性很快被它同化，后面几十代都在原地打转。

本项目每代对精英个体施加一次 **Metropolis 准则**的扰动：

- 若扰动后更好，直接接受；
- 若变差，以 `exp(-Δ/T)` 的概率接受；
- 温度 `T` 按 `cooling_rate` 逐代衰减，后期趋于纯爬山。

前期敢于走「下坡」，后期专注「上坡」，兼顾探索与开发。这就是题目里说的「引入模拟退火思想」的具体落点——它不是拼上去的，而是为了解决精英保留的固有问题。

### 工程细节

- **适应度缓存**：`FitnessEvaluator` 会把「许可-车位」对的得分缓存起来，内层循环从 O(1) 的查表代替重复计算，200 代 80 种群的耗时控制在 1.6 秒。
- **锦标赛选择**：取代轮盘赌，避免适应度绝对值小而导致的选中概率失衡。
- **优雅降级**：许可数超过车位数时，用虚拟基因占位而非重复基因，PMX 依然合法，未分配数会如实反映在结果里。
- **可复现**：`seed` 固定后结果逐位一致，测试里用这一点保证回归稳定。

## 测试

```bash
python -m unittest discover -s tests -v
# 或
pytest -q
```

12 个测试覆盖四个层面：

1. **模型层** —— 编号重复必须报错，默认权重按类型正确下发。
2. **算子层** —— PMX 子代恒为合法排列；解码后不存在一车多占。
3. **算法层** —— 同种子结果完全一致；GA 必须比随机基线高出 15% 以上；收敛曲线单调不降。
4. **边界** —— 许可数超过车位数时优雅降级，不崩溃不死循环。

其中「GA 必须比随机基线高 15%」是核心断言：它把算法有效性变成了可持续验证的约束，而不是 README 里一句无法证伪的吹牛。

## 关于这个项目的来龙去脉

这个求解器最早是我本科毕业论文《基于遗传算法的车位分配优化及停车场系统》的算法内核。论文里它还和 Django 的 CRUD、计费模块糊在一起，耦合严重，换个场景就没法复用。

这次把它彻底拆了出来：剥掉所有 Web 框架和数据库依赖，只保留纯粹的算法与领域模型，补上单元测试、可复现基准和命令行工具。拆的过程中顺手修掉了一个真实存在的边界 bug —— 许可数超过车位数时 PMX 会因基因重复而数组越界，原论文版本的测试根本没覆盖到这种情况。

Web 系统那一部分在配套仓库 `smart-parking-system` 里，它直接依赖本仓库。
